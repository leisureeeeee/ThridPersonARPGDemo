# 地面移动整合：起步、行走、停步与掉头

实现日期：2026-10-21。范围是当前单机第三人称朝移动方向转身的基础步行；没有扩展战斗、跑步、闪避、跳跃或网络预测。

## 本轮结果

- Start（起步）：用实际胶囊水平位移累计距离，反查 Katana 起步动画时间。起步序列评估器读取 StartAnimationTime，完成后由 bStartAnimationComplete 进入 Walk；不再按固定播放时长自动切换。
- Walk（行走）：原循环播放器保留，Play Rate（播放速率）引脚接 WalkPlayRate。真实速度 / 动画原始均速得到倍率，经轻微插值后限制在 0–2。低于 3 cm/s 时倍率为 0，避免站着仍原地迈步。
- Stop（停步）：保留上一轮剩余制动距离匹配和 0.12 秒尾段恢复；再次按方向输入仍可打断。
- Pivot（大角度掉头）：移动组件在地面输入方向与速度方向夹角超过 120°、速度至少 75 cm/s 时，先利用引擎原有制动降低速度。速度 <=20 cm/s 后加快朝新输入方向旋转，朝向误差 <=15° 后恢复加速。掉头总时长限制 0.75 秒，退出冷却 0.15 秒，避免异常配置/碰撞卡住。
- 普通转弯：继续移动，朝向跟随真实水平速度，而不是一改输入方向就先拧身体。普通 W+A/D 转向不重置起步时间。

大角度转向期间 bShouldMove 为 false，复用 Stop→Idle 的收脚/站立姿势；转向完成后变为 true，通过原有路径重新起步。没有在动画图中再平行复制一套方向判断。

## 分工与生命周期

1. PlayerController 继续负责 Enhanced Input（增强输入）和相机相对移动方向，没有改变按键映射。
2. AMyCharacter 用 FObjectInitializer.SetDefaultSubobjectClass 将默认 CharacterMovement 替换为 UARPGCharacterMovementComponent，保留同一个默认子对象名称，现有速度/制动和碰撞体系继续使用。
3. 新移动组件在 CalcVelocity（速度计算）中判断掉头：必要时仅在 Super 调用期间将 Acceleration 暂时置零，让引擎真正制动，随后恢复输入加速度供动画和旋转读取。PhysicsRotation（物理旋转）在普通移动时朝速度方向、低速掉头时朝输入方向旋转。组件不认识具体按键，也不直接改动画实例。
4. 动画实例在 NativeInitializeAnimation 检查起停配置并重置阶段；NativeUpdateAnimation 在游戏线程读取拥有角色/移动组件，计算数据，动画图只消费输出。动画实例通过自定义移动组件的 IsPivoting() 最小只读接口读取掉头阶段；使用普通移动组件时仍可运行起停/倍率同步。
5. 松键、失去有效拥有者、离地会清理相关动画阶段；移动模式变化、无输入或根运动接管时取消自定义掉头。没有缓存角色/世界原始指针，也没有新增退出关卡委托或定时器。

## 连续输入的处理

| 操作 | 实现的决策 |
|---|---|
| 轻点 W 后松开 | 起步可被打断，进入停步 |
| 起步中 W+A/D | 连续累积实际距离，不重播第一步 |
| 停步中重新按 W | 清空停步阶段，重新累计起步距离 |
| 行走 W 切 S | 大角度时制动、转向、再起步 |
| 制动期间 W→S→W | 新输入恢复原行进方向时取消过时的制动 |
| 松键或输入互相抵消 | 取消掉头，正常制动、收脚 |
| 离地或根运动接管 | 移动组件让出掉头控制；不是新增跳跃动画 |

为了不把短按后旧进度带到下一次起步，Start 与 Stop 仍保持进入时重置。两条输入打断过渡优先级仍为 0，完成过渡优先级为 1。bShouldMove 现在表示“允许继续地面移动动画的意图”：有水平加速度且不在掉头阶段、处于地面；不是简单的速度阈值。

## 成熟项目参考与本项目取舍

参考 Epic 的 [Lyra 动画说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-in-lyra-sample-game-in-unreal-engine) 和 [Lyra 动画适配文章](https://www.unrealengine.com/tech-blog/adapting-lyra-animation-to-your-ue5-game)：距离匹配用于起停，连续移动数据用于循环速率；完整效果还依赖脚相位、步幅和方向适配。

本项目当前只需一套 Katana 普通步行，采用一个移动组件和一个动画实例，没有复制 Lyra 的武器动画分层架构。目录中左右/后向 Start 仍引用旧 Katana 骨架路径，且没有确认可用的 Pivot/Turn 专用动画。因此本轮没有加载这些资产触发选骨架弹窗，没有批量重绑骨架或伪称完成专用转身动画。

现在的掉头是制动/转向策略，转向时复用停步与待机姿势，脚底仍可能出现旋转滑动。起停也未加入左右脚选择、步幅适配、方向适配或 IK；停止距离预测仍是平面连续近似，不等同于引擎子步制动或斜坡/碰撞预测。手感和视觉效果需要用户实测。

用户认为修复跳帧后的收尾仍急促，因此当前 VisiblePlantLead=0.35 动画秒、MaxStopPlayRate=1.0，尾段 StopSettleDuration=0.18 秒。取代上一节的 0.30/2.0/0.12 参数；保留原状态混合与惯性化输出、输入打断和物理制动。强制动时收脚及回正约需 0.53 秒，实际总时长受混合和帧率影响，效果尚待用户确认。

## 退出姿势生命周期与惯性化（2026-10-21）

修复松键/重新输入时过早把 Start/Stop 显式时间清零的问题：退出中的姿势保留到下次真正进入时再重置。现有六条过渡统一使用 Inertialization（惯性化），由状态机之后已有节点处理姿势与速度延续；仅放置节点而过渡仍用普通混合时并不会启用此效果。规则、混合时长与收脚速率保持原值。针对用户所见闪帧做了静态修复，效果仍需用户验证。
