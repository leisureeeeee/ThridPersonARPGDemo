# 基础走路：起步、行走、停步

实现日期：2026-10-21（北京时间）。这是第一版基础运动接线；效果测试由用户负责。本轮未执行 C++ 构建、显式蓝图编译验证、PIE（编辑器内运行）或动画播放测试。

## 1. C++ 改动

`Source/ThirdPersonARPG/AnimInstance/MyCharacterAnimInstance.cpp` 的 `NativeUpdateAnimation()` 仍从拥有网格体的 Pawn 读取真实水平速度到 `GroundSpeed`。另外通过通用 `ACharacter` 获取 `UCharacterMovementComponent`，读取当前水平加速度，更新 `bShouldMove`。

现在两项数据的意义不同：

| 数据 | 意义 |
|---|---|
| `GroundSpeed` | 角色实际水平速度，单位 cm/s |
| `bShouldMove` | 移动组件当前是否收到非零水平移动意图 |

松开按键后，移动意图可立即变为 false，而真实速度可能仍在制动。因此停步动画能在松键时开始，而不是等角色已经完全停下才开始。按住 W 再按 A/D 时，方向变化但输入仍非零，保持 Walk。

不依赖具体按键或 `AMyCharacter` 子类；输入仍归 PlayerController，位移仍归 CharacterMovement，动画实例只读取数据。没有有效角色/移动组件时，速度或意图恢复为零/false。没有新增反射变量，沿用原来的蓝图只读字段；旧二进制仍是旧判断，必须重新编译加载 C++。

## 2. 动画蓝图已接好

修改资产：`/Game/BP/MyCharatcer/BP_CharacterAnim`。

```text
Idle（待机） → Start（起步） → Walk（行走） → Stop（停步） → Idle
                    └──松键──→ Stop
                              Stop ──重新输入──→ Start
```

| 状态 | 动画 | 循环 |
|---|---|---|
| Idle | `AS_Idle_Seq` | 开启 |
| Start | `AS_Walk_Start_F_0_Seq` | 关闭 |
| Walk | `AS_Walk_Loop_F_0_Seq` | 开启 |
| Stop | `AS_Walk_Stop_F_0_Seq` | 关闭 |

起步和停步状态开启 Always Reset on Entry（进入时始终重置），快速重新进入时从头播放，避免接着上次残留进度播放。

## 3. 六条过渡

| 从 → 到 | 条件 | 混合时间 | 优先级 |
|---|---|---:|---:|
| Idle → Start | `bShouldMove` | 0.12 s | 1 |
| Start → Walk | 起步动画即将结束，按剩余播放时间自动切换 | 0.12 s | 1 |
| Start → Stop | `!bShouldMove`，允许松键打断起步 | 0.10 s | 0 |
| Walk → Stop | `!bShouldMove` | 0.12 s | 1 |
| Stop → Start | `bShouldMove`，允许新输入打断停步 | 0.10 s | 0 |
| Stop → Idle | 停步动画即将结束，按剩余播放时间自动切换 | 0.12 s | 1 |

数字越小优先级越高，两条打断规则优先于自动结束规则。已移除旧的 Idle ↔ Walk 直连，入口保持 Idle。状态与返回过渡的位置也已整理。

## 4. 根骨骼设置

用户已将 Start/Stop 两段动画绑定到与现用 Loop 相同的 UE4 人偶骨架。本轮再次核对骨架和骨骼轨道列表一致，只给这两段动画开启 Force Root Lock（强制根锁）、关闭 Enable Root Motion（启用根运动），并保存。

原始轨迹数据：Start 时长 1.25 s，前移约 197.07 cm；Stop 时长 1.1833 s，前移约 113.84 cm。必须消除这些位移在网格体姿势中的直接叠加，避免转向偏移及切回待机时回退。没有更改源关键帧，没有批量改攻击动画。

原有 Loop 根锁与循环保留；本轮也修正了 Idle 播放器未循环的问题。

## 5. 当前完成程度

已完成：C++ 输入意图判断、四状态六过渡、输入打断、根锁、循环、单次播放、重新进入重置、资产保存，以及状态/连接/规则的静态读回核对。

源码上一轮默认行走速度为 167 cm/s，按当前行走循环原始根轨迹均速设定。本轮不再改速度、加速度、制动或相机。蓝图或摆放实例若显式覆盖为 600，C++ 默认不会强行覆盖；测试前检查最大行走速度为 167。

## 6. 用户醒来后的最少操作

1. 保存编辑器工作，编译并加载更新后的 C++；需要完整重载时保存退出编辑器，以 Development Editor（开发编辑器）目标构建后重新打开。
2. 打开 `BP_CharacterAnim`，编译并保存。角色 Mesh（骨骼网格体组件）的 Anim Class（动画类）继续使用 `BP_CharacterAnim`。
3. 测试下列动作即可，不必重新接状态机：
   - 站立 15 秒：待机持续循环。
   - 按住 W 5 秒：起步播放一次，随后连续行走。
   - 松开 W：进入停步，然后回待机。
   - 起步刚开始就松键：能转入停步。
   - 停步过程中重新按 W：能重新起步，无需等动作播放完。
   - W+A / W+D：改变方向时保持行走循环。

记录哪一个动作有滑步、跳变或响应延迟即可；截图/视频及需要手动选择的弹窗由用户处理，助手继续做代码和可调用的编辑器 API 操作。

## 8. 停步节奏调整（2026-10-21）

用户反馈角色停止后动画过长，因此仅将 Stop 状态序列播放器的 Play Rate（播放速率）从 1.0 调到 1.5。原动画约 1.1833 秒，倍率调整后整段约 0.7889 秒；实际切回 Idle 的时机会受原有自动剩余时间过渡和混合影响。保持 Stop 单次播放，其他状态、过渡、源动画和角色制动不变。已保存并静态读回，未运行效果测试；用户编译保存动画蓝图后测试松键的收脚节奏即可，本次无需重新编译 C++。

## 9. 当前停步实现已改为距离同步（2026-10-21）

Stop 固定 1.5 倍速和自动剩余时间退出已被替代：C++ 根据制动距离选择 StopAnimationTime，Stop 序列评估器按该时间输出姿势；站稳后用约 0.12 秒完成恢复尾段，通过 bStopAnimationComplete 回待机。其余五条过渡保留。当前实现与限制、编译状态及重新生成采样的方法见 StopDistanceMatching.md。

## 10. 起步与连续移动已整合（2026-10-21）

Start 改为实际位移驱动的序列评估器，Start→Walk 读取 bStartAnimationComplete；Walk 的播放速率读取 WalkPlayRate。新地面移动组件负责大角度制动/转向/再起步，动画层读取 IsPivoting 后复用原有可打断起停流程。当前 bShouldMove 不仅要求有水平输入意图，还要求不处于掉头阶段且角色处于地面。完整说明及限制见 GroundLocomotion.md，旧章节中固定时长起步及 Live Coding 依赖说明仅反映之前阶段；本轮已完成完整构建并重新加载。
