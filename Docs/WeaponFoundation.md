# 武器类基础结构

本轮只实现武器对象结构，没有加入拔刀、收刀、点亮、输入、伤害或自动生成。

- AWeaponBase继承AActor，声明为Abstract/Blueprintable。它只创建WeaponRoot场景根组件，用于后续挂接；基类不要求具体网格类型，其他武器可选择自己的表现组件。关闭Tick，不创建空BeginPlay/Tick覆写。
- ALightsaberWeapon继承AWeaponBase，创建私有WeaponMesh静态网格组件并挂到根组件。按现有光剑StaticMesh资源类型选择组件，默认关闭物理、碰撞和重叠事件，避免将来挂到角色时阻挡自己；后续伤害检测另行实现。未硬编码资源路径。
- AMyCharacter新增私有UPROPERTY TObjectPtr<AWeaponBase> CurrentWeapon，默认nullptr，追加在已有字段后。它是世界中的武器Actor实例引用，不是TSubclassOf武器类配置，也不会生成、挂接或销毁武器。EditInstanceOnly允许对关卡角色实例指定已有武器，BlueprintReadOnly与GetCurrentWeapon提供只读访问。getter遇到已销毁对象返回nullptr；UPROPERTY使引用被UE反射/垃圾回收系统追踪，但不会自动管理Actor销毁生命周期。

调用关系为AMyCharacter→AWeaponBase，ALightsaberWeapon是其派生类型。角色不依赖光剑头文件，未来可以引用其他武器子类，具体光剑材质和音效不进入角色类。

组件在Actor原生构造函数中通过CreateDefaultSubobject建立，蓝图子类继承组件结构。没有在构造函数中生成世界Actor或加载游戏资源。

本轮未编译、未加载新类、未运行测试。新增UCLASS/UPROPERTY和构造组件需完整重新编译并加载后才会出现在编辑器。建议用户关闭编辑器、构建Development Editor再打开项目，避免仅依赖旧模块。

加载后可创建ALightsaberWeapon的蓝图子类BP_LightsaberWeapon，在WeaponMesh组件指定已导入的Lightsaber静态网格；将蓝图实例放进关卡，再在角色实例的Weapon分类将CurrentWeapon指向它。这个操作只建立引用，武器不会因此自动出现在手中或腰部。基类是抽象类型，不能直接放置。当前没有自动生成、装备接口、多人复制或存档逻辑。

## 开局武器生成与腰部挂接

本阶段在AMyCharacter中增加BeginPlay→InitializeWeapon流程：如果CurrentWeapon是有效的关卡实例则优先使用；否则按DefaultWeaponClass生成。两个来源都未配置时安静返回，不会自动使用ALightsaberWeapon或任何资源硬编码。

DefaultWeaponClass是蓝图类配置，CurrentWeapon是运行时对象实例引用，不能混用。生成参数Owner/Instigator设为角色，随后挂到角色骨骼网格的HolsteredWeaponSocket（默认scabbard1）；HolsteredWeaponOffset为相对插槽的完整变换，默认单位变换。由于挂接位置来自骨骼，正常跟随动画，不需要额外Tick同步。校准光剑朝向可调整蓝图WeaponMesh相对变换或角色挂接偏移，避免同时修改多处。

调用前检查插槽和网格；类为空、抽象类、生成失败、挂接失败均不会伪造成功结果。对已被其他Actor拥有或挂接的武器拒绝接管。挂接失败仅销毁本角色生成的对象，不销毁手动指定对象。SpawnedWeapon私有Transient引用仅追踪本角色生成的实例，EndPlay销毁该实例；借用的关卡武器仅在仍挂于角色时解除挂接。Actor的Owner指针本身不会替代这里的清理逻辑。

当前仍是单机基础对象生命周期，没有多人复制、运行时换装API、左键动作或点亮熄灭。默认挂到腰部不等于光剑已熄灭；现有剑刃材质仍需后续实现隐藏/长度控制。也没有自动修改角色动画状态。

本轮未编译/加载、未配置资产、未启动PIE或运行测试。需完整编译加载新增反射字段后，在ALightsaberWeapon派生蓝图的WeaponMesh指定Lightsaber模型，再在BP_Character类默认值Weapon分类设置DefaultWeaponClass为该蓝图、HolsteredWeaponSocket为scabbard1；自动生成方式下CurrentWeapon保持空。如果场景已有武器，也可只给角色实例指定CurrentWeapon。只有完成这些配置后，开局代码才有模型可生成/挂接。

用户验证步骤：开局观察仅一把武器随腰部运动；结束运行后无多余生成实例；重复进入游戏不会叠加。检查偏移、使用已放置武器时不重复生成，以及缺少插槽时输出日志警告。以上尚未由助手执行。

## 光剑剑刃开关基础

ALightsaberWeapon增加Ignite/Extinguish（bool返回是否成功）与IsIgnited。BeginPlay调用Extinguish；按BladeMaterialSlot（默认SaberBlade）查找材质槽，检查Masked及BladeEnabled标量存在，创建每个Actor独立的UMaterialInstanceDynamic。成功写入0或1后更新状态；失败记录警告并返回false。仅切换剑刃材质，不隐藏或缩放整个网格，不影响剑柄，不修改共享材质参数，不需要Tick。

新增/Game/Weapons/Lightsaber/M_LightsaberBlade父材质：Masked、Unlit、双面；BladeEnabled默认0驱动OpacityMask，BladeColor×Intensity×BladeEnabled驱动自发光。颜色默认蓝色，强度20。当前为立即开关，无长度动画、音效或真实灯光，发光外观与Bloom取决于项目渲染设置，尚未目视验证。

用户询问已有材质为何重建后，改为保留导入的SaberBlade材质实例入口，仅替换它的父材质，模型材质槽引用不变。Hilt完全不改；SaberBlade原FBXLegacyPhongSurfaceMaterial通用着色逻辑和灰色DiffuseColor效果并未沿用，原实例旧参数仍可能保存在文件中但新父材质不消费。应准确称为“复用材质实例，替换剑刃着色逻辑”，不能声称原视觉全部保留。原SaberBlade二进制备份在工作区.ue-lightsaber/SaberBlade-before.uasset。

Content/Python/create_lightsaber_blade_material.py可创建父材质，存在同名资产时拒绝覆盖。脚本仅创建/保存材质，现有实例换父操作由本轮编辑器操作完成。新父材质未硬编码到运行时C++，C++读取网格已有槽位材质。

材质资源已保存并读回：Masked/Unlit、BladeEnabled=0、模型仍引用原Hilt与SaberBlade。当前编辑器尚无LightsaberWeapon原生类，未编译加载C++或创建光剑蓝图、未运行PIE/测试。用户完整编译后仍需建立ALightsaberWeapon蓝图并指定Lightsaber模型，再配置角色DefaultWeaponClass；默认剑刃应隐藏。Ignite/Extinguish接口可供后续拔刀通知调用。本轮不接左键或拔刀蒙太奇。
